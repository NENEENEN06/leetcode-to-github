# 复杂度分析参考

用于根据用户实际代码估算时间与空间复杂度。宁可保守、说清假设，也不要照搬理论最优值。

## 基本原则

- 以用户代码实际结构为准：循环层数、递归深度、每次操作代价。
- 区分最坏、平均、最好情况；默认写最坏情况，必要时单独注明。
- 空间复杂度只统计随输入规模增长、需要额外保留的存储；原数组和返回值按题意决定是否计入。

## 常见时间复杂度的典型代码形态

| 复杂度 | 典型形态 |
|---|---|
| O(1) | 常数次操作、直接索引或哈希查找 |
| O(log n) | 二分、每次问题规模减半、平衡树查询 |
| O(n) | 单层循环、一次遍历 |
| O(n log n) | 排序、归并、堆、逐层而每层 O(n) 的递归 |
| O(n^2) | 双层循环、每对元素处理一次 |
| O(2^n) | 枚举所有子集/组合、斐波那契朴素递归 |
| O(n!) | 全排列枚举 |

## 常见空间复杂度的典型来源

| 复杂度 | 典型来源 |
|---|---|
| O(1) | 只使用若干变量、原地修改 |
| O(log n) | 递归栈随二分/平衡树深度 |
| O(n) | 哈希表、数组副本、队列/栈中最多 n 个元素 |
| O(n^2) | 二维 DP 表、邻接矩阵 |

## 需要特别注意的细节

- **递归**：栈深度乘以每次调用的辅助空间。
- **字符串拼接**：在 C++ 的 `string`、Java 的 `String` 等不可变对象上反复拼接可能是 O(n^2)。
- **排序**：默认比较排序 O(n log n)，但计数排序/桶排序可能是 O(n + k)。
- **哈希表**：平均 O(1)，最坏 O(n)；需按题意说明假设。
- **输入是否计入空间**：写清"不计算输入与输出"还是"包含"。

## 写法建议

- 时间：`O(n)`、`O(n log n)`、`O(n^2)` 等，用数学记号并附一句解释来源。
- 空间：`O(1)`、`O(n)` 等，说明由哪些数据结构/递归栈贡献。
- 若代码未提供或无法确定，写"无法确定"并说明缺什么信息，不要编造。
